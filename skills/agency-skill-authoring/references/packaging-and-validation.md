# Упаковка и валидация пакета навыка

Что именно проверяет `scripts/package_skill.py` и почему правила такие. Часть правил — из упаковщиков
`ai-hub-open` (`tools/build_skill_zip.py`, `scripts/package_skill.py`), часть — наша.

## Что ломает загрузку (проверяем всегда)

| Правило | Почему |
|---|---|
| Ровно один `SKILL.md`, и он в корне пакета | загрузчик навыков принимает один; второй файл в `subagents/` уже валит сборку |
| Фронтматтер — валидный YAML | самая частая причина — незакавыченное значение с `: ` внутри |
| `name` = имя папки/пакета, `[a-z0-9-]`, ≤64, без `anthropic`/`claude` | зарезервированные слова и верхний регистр ломают установку |
| `description` непустой, без XML-тегов | `<` в описании ломает схему |
| Все `references/...` и `scripts/...` из текста существуют | битая ссылка = шаг, который агент не сможет выполнить |
| В пакете нет байт-кода и артефактов сборки | `__pycache__` уезжал в коммит даже без `.gitignore` |

## Лимиты по цели

| Цель | Фронтматтер | Описание | Тело SKILL.md |
|---|---|---|---|
| `--target claude` (переносимый, внешний) | только `name`, `description` | ≤200 знаков | ≤500 строк |
| `--target hermes` (внутри, по умолчанию) | разрешены `version`, `author`, `license`, `created_by`, `metadata`, `platforms`, `tags` | предупреждение от 200, ошибка от 1024 | предупреждение от 500 строк, ошибка от 100 000 знаков |

200 знаков выбрано не по спеке (там 1024), а по худшему загрузчику: claude.ai заявляет лимит 200,
а Claude Code при авто-вызове показывает первые 250 знаков. Более длинное описание всё равно
не улучшает маршрутизацию.

Отдельный лимит у **личных Hermes-навыков**: `skill_manage create` отклоняет описание длиннее 60 знаков
всей операцией. Поэтому каркасы и правило просты: пиши ≤60 («Use when …» + два-три слова по-русски),
длинный список триггеров держи в теле — там он ничего не стоит.

## Запуск по папке конкретного навыка

Упаковщик работает с одной папкой навыка. В репозитории с раскладкой `skills/<name>/` его гоняют так:

```bash
python tools/package_skill.py --skill-path skills/<name> --target claude --check
```

В корневом репозитории (`SKILL.md` в корне, паттерн ai-hub-open) — `--skill-path .`. В шаблонах CI,
которые кладёт `new_skill.py`, оба случая уже разведены: сначала определяется путь, потом идёт цикл по всем
навыкам — несколько навыков в одном репозитории проверяются одним прогоном.

## Что не попадает в пакет

Исключаются папки `__pycache__`, `.git`, `.github`, `.venv`, `venv`, `dist`, `tools`, `tests`,
`.pytest_cache`, `.idea`, `.vscode`, `.cursor`, `node_modules`; файлы `.gitignore`, `.DS_Store`,
`package.sh`, `package.bat`, `pytest.ini`, `requirements-dev.txt`, `*.pyc`, `*.pyo`, `*.bak`, `*.swp`,
рабочие папки кампаний (`*-campaign-*`, `marketing-campaigns`).

Остальное уезжает: `README.md`, `CHANGELOG.md`, `install.py`, `requirements.txt`, `LICENSE`, `assets/`.
`LICENSE` для внешнего контура обязателен: распространять MIT/Apache-навык без текста лицензии нельзя.
Проверка на живом кейсе: `--check` на нашем же навыке показал 7 файлов в пакете и 0 предупреждений,
а на скелете внешнего навыка — 9 в пакете и 7 исключённых (`.github/*`, `.gitignore`, `tools/`).

## Секреты: остановка, а не тихое исключение

Сканируются имя файла и содержимое текстовых файлов (`.py`, `.md`, `.json`, `.sh`, `.yml`, `.txt`, без расширения).
Находка = **сборка не собирается**: если выкинуть файл молча, автор не узнает, что ключ лежал в рабочей папке.

- По имени: `.env`, `.env.local`, `.env.production`, `.envrc`, `.netrc`, `credentials.json`, `secrets.json`,
  `service-account.json`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, `*.keystore`. Шаблоны
  (`.env.example`, `.env.sample`, `.env.template`) разрешены.
- По содержимому: OpenAI `sk-…`, Anthropic `sk-ant-…`, Яндекс OAuth `y0_…`, Yandex Cloud `AQVN…`,
  Replicate `r8_…`, GitHub `ghp_/gho_/ghu_/ghs_/ghr_…`, Google `AIza…`.

Ключи хранятся вне репозитория: у навыка — в домашней папке пользователя (`~/.<name>/credentials.json`),
у сервисов — в переменных окружения агентной среды.

## `--public-check`: наш чек перед выпуском наружу

Ищет в текстах наш внутренний контекст: серверные пути (`/opt/…`), идентификаторы кабинетов вида `<ID кабинета>`,
хосты `*.beget.tech`. По умолчанию это предупреждения (внутренний пакет вправе их содержать),
с `--strict-public` — ошибки, и сборка падает. Сам сканер и его документация из проверки исключены.

## Форма архива

Внутри зипа одна папка верхнего уровня с именем навыка (`<name>/SKILL.md`), сама папка `dist/` в пакет не идёт.
Именно такую форму ждут загрузчики: zip из кнопки GitHub («Download ZIP») не годится — он заворачивает
репозиторий в папку с суффиксом `-main` и кладёт внутрь файлы, которых загрузчик не ждёт.

## Релиз и CI

- CI на каждый push/PR: `package_skill.py --check --target claude`, `python -m compileall -q scripts`,
  проверка «в индексе нет байт-кода и `dist/`». Готовые воркфлоу кладёт `new_skill.py --mode external`.
- Релиз — по тегу `v*`: пересборка пакета и прикрепление архива к релизу
  (`softprops/action-gh-release`). Без этого единственный способ получить архив — кнопка Download ZIP с её
  суффиксом `-main`.
- Версия — semver в `CHANGELOG.md`, первая запись `## <ver> — YYYY-MM-DD`. Релизные заметки для
  пользователей — `docs/releases/<tag>.md` (что изменилось для человека), CHANGELOG — технический.
