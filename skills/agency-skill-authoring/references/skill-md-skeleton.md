# Скелет SKILL.md — что и в каком порядке

Порядок секций не косметика: по нему агент находит нужное, когда читает навык первый раз.
Ниже — каркас с пояснениями. Секции помеченные (нужна) — убирать можно только осознанно.

## 1. H1 — название роли, а не темы

«Marketing Strategist — оркестратор подготовки кампаний», «Yandex Direct — пайплайн создания кампании».
Плохо: «Работа с рекламой». Роль отвечает на вопрос «кто здесь работает».

## 2. Первый абзац — что навык делает и чего НЕ делает (нужна)

Два-три предложения. Явно: «не создаёт объявления, не льёт бюджет, не дёргает API» — это защита от
расширения задачи агентом.

## 3. «Когда триггерится» / «Когда применять» (нужна)

В личных Hermes-навыках этот заголовок пиши по-английски — `## When to Use`: линтер Hermes ищет именно его
(содержимое под ним остаётся русским). В навыках для команды и для рынка имя заголовка свободное.

Список фраз Антона, по которым навык должен включаться, и отдельно —**когда НЕ триггерится**
(«если канал явно назван — иди в площадочный навык»). Первые 57 знаков `description` должны быть
самодостаточным триггером: столько видно в индексе.

## 4. «Что нужно от среды» (нужна — главная секция)

Обязательный минимум (обычно две строки: файлы в рабочей папке + диалог с подтверждением),
потом таблица необязательных способностей:

| Способность | Где нужна | Если нет |
|---|---|---|
| **Вызов MCP-инструментов** | шаги 2, 5, 10 | справочник/ручная сверка вместо живых данных; **Теряется:** ... |
| **Запуск кода** | шаги 1, 8 (`scripts/*`) | отдай команду пользователю текстом, работай с присланным выводом |
| **Чтение веб-страниц** | шаг 0 (сайт продукта) | попроси у маркетолога 5 фактов словами |
| **Субагенты / форк контекста** | шаги 3–4 | выполни шаги инлайн, работай через файлы |

У каждой строки две вещи: **фолбек** и **«что теряется»**. Навык обязан дойти до конца без любой
способности, а пропуск — печататься в артефакт шага: «пропущено: нет MCP — CPC взят из справочника,
без живых данных кабинета. Потеряно: точность прогноза. Как добрать: подключить MCP и пересчитать».

Молча упрощённый результат — хуже честно недобранного.

## 5. «Главный принцип» / «Как работаем»

Маршрут одним абзацем + жёсткие правила: пошагово, гейт на каждом шаге («✋ Подтверди шаг N»),
рабочая папка с артефактами, правила режима (пошаговый/быстрый).

## 6. Шаги воронки — по одному разделу на шаг (нужна)

На каждом шаге три блока:

- **Вход** — какие файлы читает (артефакты предыдущих шагов);
- **Что делаем** — список операций, без воды;
- **Артефакт** — имя файла и поля (скажем, `01_brief.md`, `channel_history.json`);
- **Гейт** — что показать человеку и какой вопрос задать.

Именование артефактов — `NN_имя.md`. Если шаг можно пропустить (нет способности среды) — так и напиши,
и добавь строку про пометку о пропуске.

## 7. «Как использовать references» / «Как использовать scripts»

Таблицы: «файл → на каком шаге → что внутри». Для скриптов — вызов одной строкой и что он пишет.
Все пути, упомянутые здесь, должны существовать в пакете — упаковщик это проверяет.

## 8. «Стиль работы» (нужна)

Императивные правила для агента, коротко: не задавать вопросов пачкой, артефакт — в файл, в чат —
сводка 5–10 строк, гипотеза вместо пустого вопроса, «не знаю» лучше выдуманного, не защищать красивую
цифру, ссылки на references обязательны.

## 9. «Возобновление» (нужна)

Что делает агент, когда человек говорит «продолжаем»: где искать рабочую папку, какой файл состояния
читать, что не спрашивать заново (`_state.json` → `current_step`).

## 10. «При сбое шага» / «Границы»

Порядок разбора сбоя (не хватает входа — вернись на шаг-источник) и явный перечень того,
чего навык не делает.

## Гигиена текста

- Документация — по-русски; названия полей и методов API — как в оригинале площадки (`adimages_add`,
  `utm_source`): переведённое имя поля агент не найдёт в документации.
- Одна мысль — одна строка списка. Длинные объяснения — в `references/`, в SKILL.md — правило и указатель.
- Числа лимитов, порогов, цен — с источником и датой проверки: «проверено 07.10.2026 на кабинете X».
- Не оставлять «UPDATE: вообще-то…» — переписывать правило на месте, иначе старое указание продолжает действовать.
- Серверные пути (`/opt/…`) в тексте допустимы только для внутреннего контура: перед внешним релизом
  их вычищают или заменяют на относительные.
